DOCUMENT 61: Niagara Fluids in Unreal Engine
Source URL: https://dev.epicgames.com/documentation/unreal-engine/niagara-fluids-in-unreal-engine
Niagara Fluids is a plugin that enables you to create 2D and 3D fluid simulations using the Niagara visual effects system. These simulations can represent fire, smoke, water, and other fluid effects.
Key Features
2D and 3D Gas Simulations — Create fire, smoke, and other gas-based effects.
2D and 3D Liquid Simulations — Create water and other liquid-based effects.
Real-time Simulation — Fluids simulate in real-time during gameplay or cinematic playback.
GPU-based Computation — Simulations run on the GPU for high performance.
Collision Support — Fluids can collide with static geometry in the scene.
Lighting Integration — Simulated volumes can interact with scene lighting.
Niagara Integration — Full integration with the Niagara particle system for rendering and behavior control.
Setup and Requirements
Enable the NiagaraFluids plugin in Edit > Plugins.
Restart the editor.
Create a new Niagara System using the Niagara Fluids template.
Simulation Types
2D Gas (Grid2D Collection)
Simulates gas behavior on a 2D grid. Useful for effects like fire, smoke, and heat haze that can be represented in a plane.
3D Gas (Grid3D Collection)
Simulates gas behavior in 3D space. Useful for volumetric effects like smoke plumes, explosions, and atmospheric phenomena.
2D Liquid
Simulates liquid behavior on a 2D grid. Useful for effects like water surfaces, splashes, and flowing liquids in a planar representation.
3D Liquid
Simulates liquid behavior in 3D space. Useful for effects like pouring water, splashing, and volumetric liquid interactions.
Important Notes
Simulations must be run in Play in Editor (PIE) mode to see the fluid dynamics update.
Ensure your graphics card drivers are up to date for best performance.
Quality and performance tradeoffs can be adjusted through simulation resolution settings.

DOCUMENT 66: Audio in Unreal Engine
Source URL: https://dev.epicgames.com/documentation/unreal-engine/audio-in-unreal-engine
Unreal Engine provides a comprehensive audio system for creating immersive soundscapes in your projects.
Key Audio Systems
Core Concepts
Sound Waves
Sound Wave assets represent raw audio files imported into Unreal Engine. Supported formats include WAV, OGG, and AIFF.
Sound Classes
Sound Classes group sounds together for collective volume control and mixing. They form a hierarchy where child classes inherit properties from parent classes.
Sound Mixes
Sound Mixes dynamically modify Sound Class properties at runtime. They can be activated by gameplay events to create dynamic audio changes (e.g., muffling sounds when underwater).
Submixes
Submixes route audio to dedicated processing buses where effects like reverb, EQ, and compression can be applied to groups of sounds.

MetaSounds use a node-based graph where: - Input nodes receive external data (gameplay parameters, trigger events). - Process nodes perform audio synthesis and processing (oscillators, filters, envelopes). - Output nodes send the final audio to the sound system.

DOCUMENT 69: Spatial Audio in Unreal Engine
Source URL: https://dev.epicgames.com/documentation/unreal-engine/spatialization-overview-in-unreal-engine
Overview
Spatial audio is the technique of giving sounds a perceived location in 3D space around the listener. Unreal Engine supports several spatial audio technologies.
Panning Methods
Stereo Panning
The simplest form of spatialization. Sound is distributed between left and right speakers based on the source’s horizontal position relative to the listener.
Surround Sound
Uses multiple speakers arranged around the listener (5.1, 7.1, etc.) to create a more immersive sound field.
Vector-Based Amplitude Panning (VBAP)
Distributes sound across multiple speakers using vector calculations. Provides smooth positioning between speaker locations.
Ambisonics
A full-sphere surround sound technique that captures directional audio information. Supports both first-order and higher-order Ambisonics for increased spatial resolution.
HRTF-based Binaural Spatialization
Uses Head-Related Transfer Functions to simulate how sound reaches the ears. Provides the most realistic spatial audio when listening with headphones.
Platform Support

DOCUMENT 71: UMG UI Designer Quick Start Guide
Source URL: https://dev.epicgames.com/documentation/unreal-engine/umg-ui-designer-quick-start-guide-in-unreal-engine
Overview
This quick start guide covers how to set up user interfaces with the UMG UI Designer. UMG (Unreal Motion Graphics) is Unreal Engine’s visual UI authoring tool. This guide walks through creating a menu UI and an in-game HUD (Head-Up Display) showing Health, Energy, and Ammo.
Project Setup
Before starting, create a new project using the First Person template with Blueprints enabled.
Creating a Widget Blueprint
In the Content Browser, right-click in the content folder.
Select User Interface > Widget Blueprint.
Name it WBP_Menu.
Adding Widget to Viewport
To display the menu, you need to add the widget to the viewport:
Open the Level Blueprint.
Right-click and search for Create Widget node.
Set the Class pin to your WBP_Menu widget.
Drag off the Return Value pin and select Add to Viewport.
Connect this to a BeginPlay event or an input action to trigger the menu.
Removing the Widget
To close/dismiss the menu, call Remove from Parent from a widget reference. This is typically connected to a button click event (e.g., “Resume” or “Quit” button).
Designing the HUD Layout
This section creates a HUD with three progress bars (Health, Energy, Ammo) using a Horizontal Box layout:
Create a new Widget Blueprint called WBP_HUD.
In the Widget Designer, add a Horizontal Box to the canvas.
Add three Progress Bar widgets inside the Horizontal Box.
Set the Fill Color and Opacity to distinguish them (Green for Health, Blue for Energy, Orange/Yellow for Ammo).
Set Percent to 1.0 initially (full).
Scripting the Progress Bars
Creating the Binding
Select the Health progress bar in the Designer.
Next to Percent in the Details panel, click Bind > Create Binding.
This creates a Get Percent function in the Graph tab.
Accessing Player Data
Inside the binding function: 1. Right-click and add a Get Owning Player Pawn node. 2. Drag off the return value and add a Cast To [YourPlayerClass] node. 3. From the cast result, access the relevant variable (e.g., Health, Energy, Ammo). 4. Divide the current value by the max value to get a 0.0-1.0 range. 5. Return this value as the output of the binding function.
Repeat this process for each progress bar.

DOCUMENT 80: State Tree in Unreal Engine
Source URL: https://dev.epicgames.com/documentation/unreal-engine/state-tree-in-unreal-engine
Overview
StateTree is a general-purpose hierarchical state machine combining Selectors from Behavior Trees with States and Transitions from state machines.
Key Characteristics
Hierarchical — States nest within other states, creating a tree structure.
Selector-based — Uses selectors for choosing which state to execute.
Transition-driven — States transition to others based on conditions.
Efficient — High-performance execution for complex AI and gameplay logic.
Flexible — For AI, animation state management, gameplay flow control.
How It Works
Evaluates selectors at each hierarchy level to determine the active state. When conditions change, transitions fire. Each state contains:
Enter Conditions — Requirements to enter the state
Transitions — Rules for when/where to transition
Tasks — Actions while in the state
Sub-states — Nested child states

DOCUMENT 81: Networking Overview for Unreal Engine
Source URL: https://docs.unrealengine.com/5.4/en-US/networking-overview-for-unreal-engine/
Unreal Engine uses a client-server model for multiplayer games. The server acts as the Authority, while players connect as clients. The actual game state is adjusted by the server. Players control their Pawn as Autonomous Proxies, and the server replicates changes to each connected client.
Key Concepts
Authority: The server has authority over game state.
Replication: The process of synchronizing data between server and clients.
RPCs (Remote Procedure Calls): Functions called on one machine that execute on another.
Actor Replication: Actors can be configured to replicate from server to clients.
NetUpdateFrequency: Controls how often an actor replicates per second.

DOCUMENT 83: Performance and Bandwidth Tips
Source URL: https://dev.epicgames.com/documentation/unreal-engine/performance-and-bandwidth-tips-for-unreal-engine
Key Tips
NetUpdateFrequency: Reduce to decrease replication frequency. Lower = less bandwidth and CPU.
Dormancy: Put actors in dormant state when not relevant. Dormant actors don’t replicate until woken.
Relevancy: Actors not relevant to a client are not replicated. Based on distance and other factors.
Replication Graph: For large-scale multiplayer, controls replication per-actor.
Property Replication: Only mark properties as replicated if necessary. Derive state from existing properties when possible.
Quantization: Use FVector_NetQuantize to reduce bandwidth for vectors.
RPC Parameters: Be careful with FName in RPCs — sends full string, can be expensive.
