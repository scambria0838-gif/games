# Proposal: Expose Meter Drive-By lean / brake / health / melee into GameSpec

**Status:** proposal only  
**Explicit:** no production code — proposal only

## Context

Live feel knobs for lean, brake, health, and melee already exist in `packages/shared/src/meter-driveby/tuning.json`. GameSpec today only exposes `melee` id + course/env overlays. ForgePlay cannot yet author arcade feel without forking tuning.

## Proposed GameSpec fields

Additive optional block on `GameSpec`:

```ts
feelOverrides?: {
  // Lean steer (maps → leanAuthorityBase, wobbleGain)
  leanAuthorityBase?: number; // default 3.7, range 2.5–5.0
  wobbleGain?: number;        // default 0.9, range 0.4–1.4

  // Brake / stability (maps → brakeFrictionBonus, brakeStabilityDrain, stabilityRecover)
  brakeFrictionBonus?: number;   // default 2.8, range 1.5–4.0
  brakeStabilityDrain?: number;  // default 0.28, range 0.12–0.45
  stabilityRecover?: number;     // default 0.28, range 0.12–0.45

  // Health / damage (maps → healthMax, hardHitDamage, softScrub, meterRamChipDamage)
  healthMax?: number;            // default 100, range 60–140
  hardHitDamage?: number;        // default 18, range 10–28
  softScrub?: number;            // default 0.08, range 0.04–0.14
  meterRamChipDamage?: number;   // default 4, range 2–8

  // Melee feel per loadout (overrides tuning.melee[id]; GameSpec.melee still picks id)
  meleeArcRad?: number;          // flamingo 1.5 / sign 0.7 baselines; range 0.5–2.0
  meleeReach?: number;           // flamingo 2.2 / sign 2.6; range 1.6–3.2
  meleeCooldownTicks?: number;   // flamingo 21 / sign 18; range 12–30 (60 Hz ticks)
}
```

**Merge rule:** omit field → use `tuning.json` default for selected `melee`. Keep ranges arcade-safe; reject out-of-range at parse (Zod later).

**Suggested prompt heuristics (generator only, not code here):**
- “slippery / wobbly” → ↑ `wobbleGain`, ↓ `leanAuthorityBase` slightly
- “tank / durable” → ↑ `healthMax`, ↓ `hardHitDamage`
- “heavy swing” → ↑ `meleeReach` / `meleeArcRad`, ↑ `meleeCooldownTicks`
- “tight brakes” → ↑ `brakeFrictionBonus`, slightly ↑ `brakeStabilityDrain`

## Compatibility vs existing knobs

| Existing | Interaction |
|----------|-------------|
| `softDensity` / `meterSpacingMult` | Orthogonal — course layout; feelOverrides do not change spawn density |
| `forceGuard` / `trapChance` | Orthogonal — guard still uses tuning `guardDamage`/`guardSpeed` until a later guard block |
| `duskBias` / `rainBias` | Presentation; `rainBias` already pairs with `frictionScale` — feelOverrides should **not** re-scale µ; leave friction to `env.frictionScale` |
| `frictionScale` | Keep as sole surface µ multiplier; do not add duplicate friction fields in feelOverrides |
| `melee` | Remains loadout id (`flamingo` \| `sign`); feelOverrides only retune arc/reach/cooldown for the chosen id |

Additive: all fields optional; empty `feelOverrides` ≡ current playable.
